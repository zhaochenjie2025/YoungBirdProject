# PRD 质询：底部导航与历史能力

2026-11-25。起因：定稿视觉 `explore/caloriesnap-final.html` 的底部是四栏
（今日 / 拍一张 / 本周 / 分享），而现有工程是四栏（今日 / 记录 / 本周 / 历史），
PRD 又明确要求历史能力。三者不一致，需要判定「改导航」还是「改别处」。

## 一、PRD 原文怎么说

PRD 只约束**能力**，不约束**导航结构**。相关两句：

- 三.3：“历史页支持按日期查看、修改和删除。”
- 三.3：“首页展示当天已记录的餐次与热量，周视图展示最近七天的记录。”

全文没有出现“底部导航”“标签栏”“四栏”之类的结构要求。
所以“历史页”是一个**功能载体**的名称，不是一个必须占导航格的位置。

## 二、定稿实际提供了什么

逐项核对 `explore/pending/final-logic.js` 与 `final-markup.html`：

| PRD 能力 | 定稿 | 证据 |
|---|---|---|
| 按日期查看历史记录 | 缺 | 只有当天视图，无日期切换入口 |
| 修改记录 | 缺 | 全文件无编辑流程 |
| 删除记录 | 缺 | 全文件无删除流程 |
| 周视图看七天 | 有 | `#s-week` |
| 首页看当天 | 有 | `#s-today` |
| 拍照识别确认 | 有（演示数据） | `#s-detect`，`DETECT` 常量写死 |
| 分享 | 有 | `#s-share`，Canvas 1080×1350 |

结论：定稿缺的是**三项 PRD 能力**，不是“少一个导航格”。
即使把“历史”塞进导航，点进去也没有内容，因为定稿根本没做那三件事。

## 三、四种处理方案

| 方案 | 做法 | 代价 | 判断 |
|---|---|---|---|
| A | 导航加第五栏“历史” | 320 宽每栏 64px；定稿的手账感被稀释 | 只解决入口，不解决内容 |
| B | 历史并入本周页 | 不加栏 | “七天”与“全部”语义混用，PRD 的按日期浏览无处安放 |
| C | 分享移出导航 | 分享本来就有结果页入口 | 分享是团队要的亮点，藏起来可惜 |
| D | **今日页做成日期容器** | 需要新做日期翻页控件 | **采纳** |

## 四、采纳方案 D 的理由

“今日”这一屏本质就是一个日期容器。给它加上左右翻页：

- 翻到今天 = 今日页，与定稿完全一致
- 往前翻 = 看历史某天，PRD 的“按日期查看”由结构自然满足
- 每条记录展开后有“修改 / 删除”，PRD 的另两项能力同时到位
- 导航保持定稿的 4 栏，美术方案不动
- 日期翻页可以做成手账翻页的样式（纸页掀起、日期压印变化），不背叛母题

这样 PRD 三项能力与定稿美术**不冲突**，不需要改 PRD，也不需要改导航。

## 五、需要 Sou39O 确认的点

1. 日期翻页的默认跨度：逐日翻，还是“前一天 / 后一天”按钮？
2. 翻到“今天”之后能否继续往后翻（未来日期）？建议不能。
3. 修改与删除的入口：长按记录，还是记录展开后的按钮？建议后者（可发现性更好）。
