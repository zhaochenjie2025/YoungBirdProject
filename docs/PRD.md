# 卡路里拍立得 CalorieSnap 产品需求文档

**版本 v0.1｜雏雁计划首版原型**

首版围绕一个场景设计：**北邮学生在食堂吃完一餐，可以通过逐菜拍照和手动补录，把多道菜保存为一条饮食记录。** 系统根据用户确认的菜品和食用份量估算热量，展示估算依据，并提供基于已记录餐食的膳食建议。

按确认的范围，**整盘餐食可以记录，逐菜拍摄与手动补录可以混用**。首版以公开营养资料和团队自行称重为数据基础。产品形态沿用立项方案中的手机网页，暂按免登录、记录保存在当前浏览器设计。

## 一、目标用户与使用场景

目标用户是经常在校园食堂就餐、希望了解饮食摄入或调整膳食搭配的学生。首版解决三个问题：

- **记得快。** 常见菜品可拍照识别或搜索添加，份量可用半份、标准份等选项填写。
- **改得动。** 菜名、份量或餐次填错后可以修改。修改后，单餐汇总和历史统计同步更新。
- **看得懂。** 用户可以看到热量估算用了什么份量和营养资料，以及哪些菜仍缺少数据。

典型场景是一份由米饭、番茄炒蛋和清炒青菜组成的午餐。用户拍照识别番茄炒蛋，搜索添加米饭和青菜，把米饭改为半份，确认后保存为一条午餐记录。

## 二、核心流程

**新建一餐 → 拍照或搜索添加菜品 → 确认菜名与实际食用份量 → 查看热量汇总 → 保存记录 → 查看饮食回顾**

一餐可包含多道菜。拍照识别和手动添加共用同一份餐食草稿。用户可以在保存前增删菜品、修改份量，也可以保存后回到详情页更正。

## 三、首版功能需求

### 1. 添加菜品与识别确认

用户可直接拍摄单道菜，也可从相册选择照片。系统展示最多三个候选菜名，由用户选定后加入当前餐食。用户也可直接搜索菜品，搜索支持标准菜名和常用别名。

图片模糊、识别结果不确定或未找到匹配时，页面提供重拍、搜索和手动记录入口。对菜品库之外的食物，用户可保存自定义菜名并标记为**待估算**。

**验收要求**　同一餐可混用拍照与手动添加。单次识别超时或失败后，已添加的菜品仍保留，用户可以继续手动完成记录。

### 2. 确认份量与计算营养

按**实际吃下的份量**记录。用户可以选择半份、标准份等常用选项，也可以输入已知克数。每个选项显示对应的估计克数，标准份按菜品分别设置，有实测样本时采用团队称重数据。

系统根据食用重量和每100克营养数据计算热量，以及可获得的蛋白质、脂肪和碳水化合物。匹配到近似菜品时，结果页注明采用的参考条目。有依据支持上下限时，可给出热量范围，并说明主要差异来自份量、用油量或配方。

**验收要求**　同一道菜从标准份改为半份后，该菜的热量、营养素及整餐汇总同步更新。含待估算菜品的一餐仍可保存，页面显示"已估算热量"和待估算菜品数量。营养数据缺失时显示"暂无数据"。

### 3. 单餐结果与历史记录

单餐结果优先展示**已估算热量、菜品明细和待估算状态**。展开菜品可查看份量、营养数据来源和估算说明。保存时记录就餐时间和餐次，历史页支持按日期查看、修改和删除。

首页展示当天已记录的餐次与热量，周视图展示最近七天的记录。无记录的日期显示"未记录"，含待估算菜品的日期显示数据不完整。

**验收要求**　刷新页面后可在当前浏览器找回已保存的餐食。修改或删除记录后，日统计和周统计与餐食明细一致。

### 4. 营养大模型建议

用户可根据当前一餐或所选日期的记录生成简短建议。系统把菜品、已算出的营养数据、记录完整度和相关营养知识提供给大模型，由模型解释膳食搭配，并给出一两条适合校园食堂的调整建议。

例如，记录中只有米饭和肉菜时，可以提示"这餐的记录里暂未见蔬菜，下次可搭配一份绿叶菜"。模型引用系统提供的数值，缺失项保留为待估算。单餐记录主要用于解释本餐，连续记录可用于回顾近期搭配。

**验收要求**　建议中的热量和营养素数值与结果页一致。建议生成失败时，用户仍可查看估算结果、保存餐食和查看历史。

## 四、数据与验收指标

菜品库优先覆盖**不少于20类校园常见菜品**。每个条目记录标准菜名、别名、烹饪方式、每100克营养数据及其出处、参考份量及其来源。称重样本记录去除餐具后的食物重量。食堂实际配方暂未取得时，采用可追溯的近似条目，并在结果页标明。照片按识别所需处理，历史记录默认保存菜名、份量和结果。

以下指标沿用立项草案，作为开发和结题测试目标：

- **识别数据。** 累计整理不少于500张有效图片，其中独立测试图片不少于100张。同一份餐食的不同角度照片归入同一数据分组。
- **单菜识别。** 对已覆盖菜品的独立单菜测试图，用户确认前的首选识别准确率目标为85%。没有返回候选的测试样本计入分母。
- **热量估算。** 使用不少于60份配方可核查、食用部分已称重的参考餐食，单餐热量估算的平均绝对百分比误差目标为25%以内。正式测试中，用户通过日常份量选项完成记录，实测重量和配方用于计算参考值。配方未知的真实食堂餐食单独检查菜品匹配、份量估算和记录流程。
- **使用效率。** 邀请不少于15名学生完成同一项测试任务：记录一份含三道菜的餐食，其中至少一道通过拍照添加，至少一道通过搜索添加。任务完成率目标为90%，成功任务从新建到保存的中位用时目标为60秒以内。
