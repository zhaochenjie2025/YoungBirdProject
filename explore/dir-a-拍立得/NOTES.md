# 方向 A — 拍立得 / 胶片 / 纸感

## 核心母题
「一餐 = 一张即时成像相纸」。照片是这份饮食记录的实体：菜名与克数用手写体
直接写在相纸下沿的留白（chin）上，热量用橡皮图章盖在角落。整套界面是一间暗房：
深色的墙、暖橙的安全灯（= 快门/拍照那一个动作），相纸是唯一发光的东西。

## 三个关键工艺细节
1. **相纸三件套**（`.print`）：真正的即时成像比例 —— 照片区 1:1、左/上/右窄边、
   下沿留白更宽放字；叠加纸纤维颗粒（`--grain` SVG 噪声，multiply 混合）、
   显影区压印内阴影，并带轻微随机旋转（扇形摊开时 ±1°）。
2. **抽帧式的「显影」**：拍照不是弹 toast，而是把新菜作为一小格「接触印相」
   浮现在胶片条上，`develop` 关键帧只动 opacity/scale；结果页大图同样走这层渐显。
3. **35mm 胶片条周视图**：左右两列齿孔（`--sprocket` 平铺）+ 深黑片基，
   每天一帧；「未记录」用空白帧 + 破折号，「数据不完整」打琥珀色待估算章。

## 性能取舍
- 零依赖、零网络：图片全部是内联 SVG（俯拍餐盘），渐变定义抽成单份 sprite，
  避免多图同名 id 冲突；不过滤/不模糊、不做 WebGL。
- 动画只用 transform / opacity（显影、快门按压、闪白），尊重
  `prefers-reduced-motion`。
- 单文件约 45 KB，远低于 120 KB；390 与 360 宽均无横向溢出、无 console 报错。

## 最具原创性的一处
「显影接触印相条」：新建一餐时，主按钮（快门）在上方当绝对焦点，下方相纸
留一条胶片式显影区，拍到的菜一格一格浮现 —— 把「拍照录入」这件事本身做成了
照片正在显影的物理隐喻，而不是通用的列表 + 卡片。
