# 方向 M · 以 A（拍立得）为底稿的定稿版

产出：`explore/round4/dir-m-定稿/index.html`（单文件 111.4 KiB，零依赖零网络）

## 一、保留了什么（A 的母题与工艺，团队投票的基础）
- **母题**：一餐 = 一张即时成像相纸；整套是暗房，暖橙安全灯，相纸是唯一发光物（值域反转）。
- **工艺**：`.print` 相纸自发光 halo + halation、纸芯三层边 + 下沿 1.5px 实体厚度、纸纤维颗粒；`.print__chin`
  凸版压印（text-shadow 双色错版）；`.contact` 显影接触印相条（develop 只动 opacity/scale + 尾部未曝光片基）；
  `.shutter` 车削机械快门（滚花齿边 + 车纹环 + 黄铜光圈刻度 + 按压内圈真陷回弹）；35mm 齿孔、帧号、日期压印。
- 这套全部原样保留，新功能在它的材质规则上生长，不另起炉灶。

## 二、三个问题：方案 / 为什么 / 否决了什么

### 问题 1：七日视图读不出营养构成
- **方案（光楔 / step wedge）**：保留 35mm 胶片外壳，内部每格是一支「柱」。柱高 = 当日热量；柱内三层染料色带
  （碳水暗青 / 脂肪铜橙 / 蛋白暖白）由下到上叠放，段高 = 该营养素**供能占比**（4/9/4 kcal/g 换算，实时算不写死）。
  y 轴三档刻度 + 周平均虚线（标「均316」在右侧刻度槽）；未记录日给**未曝光矮片基档**（约 34% 高 + 竖排「未曝光」+
  银盐斑驳），语义是「未知」不是「0 千卡」。下方一张暗房案头「本周营养构成」说明卡（供能占比条）。
- **为什么这样选**：A 的世界里柱不该是墨在纸上的数据块，而是「光透过三种染料层投在片基上的密度」——所以柱用
  `mix-blend-mode:screen` 叠加、底部透片基雾，帧号（23A/22A…）钉在每帧片基上，读作「七格胶片」而非图表。
  这既满足了「看到每天多少 + 构成」的功能，又不背叛 A 的胶片语言。
- **否决**：① 直接照搬 K 的苹果白底柱（会把暗房变成浅色仪表盘，反母题）；② 用系统蓝绿配色（团队原话要「暗房的暖调」，
  遂用琥珀/铜/暗青，不用系统色）；③ 保留纯胶片条不显示构成（不解决问题）。

### 问题 2：分享功能（最大增量）
- **方案（样片试印 proof print）**：新增「留个样张」页，三档（这一餐 / 这一天 / 这一周）。分享物不是截图，是一张
  **1080×1350 的冲印件**：暗房底 + 安全灯暖光 + 相纸本体（自发光 + 纸芯三层边 + 下沿厚度）+ 照片 + 热量大数字 +
  条目 + 营养条 + **红蜡笔圈**圈住成绩 + **橡皮图章「已记」**（油墨缺墨）+ 一句手写感收束。
- **生成方式（能不能真存）**：**手写 Canvas 2D**，不引 html2canvas。相纸/文字/营养条全是 canvas 原生绘制；菜品照片
  把内联 SVG 序列化成 data URI 再 `drawImage` 烘进画面。产物 `canvas.toDataURL('image/png')` → `<a download>`。
  **已实测**：Playwright 触发 `#sh-save`，拿到真实下载 `caloriesnap-*.png`，1.3 MB，PNG 签名 `89504e47` 校验通过；
  浏览器拦截下载时降级提示「长按预览图另存」。
- **为什么这样选**：成就感来自「这张值得发」。相纸 + 蜡笔圈 + 印章是老师批改/暗房打样的真实动作，比一个炫耀式渐变大卡
  更贴 A、也更耐看。
- **否决**：① 分享一张普通数据卡（截图级，无成就感）；② 假连笔手写签名（我试过，Canvas 上读起来像 "00S"，遂改橡皮图章，
  更可信也更可控）；③ 用 `destination-out` 做蜡笔断点（会把相纸打穿成黑洞，改为纸色短弧覆盖）。

### 问题 3：识别确认页要更轻松（**整段拍摄流程**，不只结果页）
- **方案（整段「窗外拍摄间」）**：团队说的是「拍照 → 看识别 → 选菜」这一整段，所以我把 **`拍一张` 页 + `识别选菜` 页
  两屏一起**切进同一间明亮房间（`#app.on-daylight`）：奶油/嫩绿日光背景、斜射日光柱、浅木色工作台底栏、顶栏墨线隐去。
  机械快门保留（车纹/滚花/黄铜刻度都在），但外壳从暗房冷钢换成**日光下的暖铜旋钮**，橙色镜片仍是唯一暖点——
  骨架不变、环境光从安全灯换成日光。识别结果用 die-cut 白边贴纸卡 + Twemoji 菜品图 + **墨印勾章**；
  主 CTA 是一枚**暗房「盖进这一餐」压印章**（不是电商绿胶囊）；返回键做成撕票式小纸签。
- **选菜那一步**：是的，`s-detect` 与 `s-new` 共用 `on-daylight`，选菜页整屏日光、贴纸卡、印章勾选，全部一起改。
- **怎么和暗房共存**：这是「走出暗房到亮处取景/看片」的物理叙事——暗房负责显影（今日/本周/结果页仍是暗房），
  拍摄间负责取景与挑选（日光）。结果页 `s-result` 落回暗房（照片「显影好了」），闭环自然，不是硬换皮。
- **否决**：① 只改结果页不改入口（评审反馈「进到这一页完全没感觉不一样」，已修）；② 全站换风格（团队只针对此段）；③ 保留暗房但加个明亮小卡（不够，看不出换房间）。

## 三、融合的其他方向
- **K 的应用外壳布局**（直接采用，工程正确性）：`body` 竖向 flex，`.app-scroll` 自己滚动、底边止于导航上沿，导航
  `relative` 参与布局。**根治**了 A 原来 `position:fixed + padding-bottom` 的遮挡隐患。
- **K/E/J 的周柱**：刻度 + 平均虚线 + 未记录日三态，翻成胶片光楔（见问题 1）。
- **L 的 die-cut 贴纸感**：用在识别页贴纸卡、分享卡这类「小元素」上（白边三件套 + 微旋转）。
- **E/G/L 的数字滚动 Number Ticker**：今日大数字、周合计、草稿合计用 rAF easeOut 逐值滚动，reduced-motion 落值。
- **自动膳食建议**：A 原始是写死文案；本版改成**规则链引擎**（无蔬菜→无主食→碳水>65%→蛋白<15%→脂肪>50%→均衡），
  数值全部从菜品库 per100×克数实时算（例：勾掉红烧肉后，文案里的「番茄炒蛋、米饭」自动跟着变，47 千卡为青菜真值）。

## 七、未做到 / 局限（如实）
- 菜品「照片」仍是手绘矢量（A 原有资产），达不到实拍摄影层次；受零依赖 + 体积约束，未接位图资产管线。
- 识别流程用内置演示数据模拟（真实产品应调 DeepSeek 封闭选择）；扫描条与「认出 3 道菜」是演示态。
- 分享下载在部分移动浏览器（iOS 旧版）可能被拦，已做「长按另存」降级提示。
- 光楔的 3D 化（半透体积柱）经评估超出零依赖 ≤120KB 预算，按 Skill 退出口保留 2D 的密度/片基雾表达。
