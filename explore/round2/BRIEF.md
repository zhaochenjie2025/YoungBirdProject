# 第二轮视觉探索 · 统一作业书

## 这一轮和第一轮的区别（必须先理解）

第一轮的四个方向是自创母题，问题是**没有真正借力成熟的设计体系与组件机制**，导致成品像"自己想的"，而不是"行业里做到过的最好水平"。

这一轮改成**参考驱动**：

1. **必须先读** `~/.claude/skills/creative-frontend/references/scaffolds-and-refs.md`
2. 在动手前，从里面**点名挑 2~3 个具体机制**（必须有名字，如 `Scroll Stack`、`Number Ticker`、`Bento Grid`、`Border Beam`、`Option Wheel`、`Sticker Peel`、`Tear Ticket`），写进 NOTES 的方案段
3. 借用的是**机制与算法**，不是默认模板皮。必须换成本项目的材质、颜色、容器语言
4. 也要参照现实世界里该风格的**真实标杆**（如做 Material 风就照 Material 3 规范，做 Apple 风就照 iOS 26 的液态玻璃与 spring 动效曲线）

**禁止**只写"我借鉴了 React Bits"却说不清借了哪个组件的哪个机制。

## 产品约束（所有方向相同）

产品：卡路里拍立得，北邮食堂饮食记录。手机网页。

必须呈现四屏（可做成可切换）：
1. **今日**：今天已记录的餐次与热量，含空状态
2. **新建一餐**：拍照入口（明显主操作）+ 已添加菜品列表 + 实时汇总热量
3. **单餐结果**：一道菜明细展开（份量 / 每100克 / 本处折算 / 出处）
4. **周视图**：最近七天，含「未记录」与「数据不完整」两种状态

数据真实性要求：
- 热量 553 千卡 = 午餐 321 + 早餐 232 这类加法必须自洽，不许写死一个和明细矛盾的总数
- 标注 `kcalRange` 的菜要能体现区间
- 缺失值显示「暂无数据 / 待估算」，**绝不用 0 冒充缺失**

## 硬约束

- **手机优先**：设计基准 390×844，必须适配 360 宽窄屏，`viewport-fit=cover` + 安全区
- **性能第一**：单文件 ≤ 120 KB；零外部依赖（不用 CDN 字体、不引库、不联网）；
  动画只用 transform/opacity；尊重 `prefers-reduced-motion`
- **自包含**：一个 `index.html`，内联 CSS/JS，系统字体栈或内联 SVG
- **必须自测**：390 与 360 宽无横向溢出；console 零报错；四屏可切换

## 流程（必须走完）

1. 加载 `creative-frontend` Skill
2. 读参考库，选定机制，写方案
3. 做完（至少四屏全部可见）后，**自己派生质询代理**：
   - 用 Agent 工具，`subagent_type: s39o-aesthetic-critic`，`model: haiku`
   - 自己起临时静态服务截图存到 `explore/.shots/<你的目录名>/`（已 gitignore）
   - 必截：`view.png`（390×844 视口，DPR 2）、`full.png`（整页）、2~3 张 200% 局部特写、可选剪影块状图
   - 跑 `node ~/.claude/skills/creative-frontend/scripts/slop-scan.mjs explore/round2/<你的目录>/index.html`
   - 交给质询代理的**只能**是：截图路径、slop-scan 完整输出、一句话母题、**你借用的机制清单**、标杆参照
   - **严禁**向质询代理解释设计理由、时间压力、技术妥协
4. 按《视觉质询单》逐条返工，**最多 2 轮**；第 2 轮只复核首轮必改项
5. 返工后重跑 slop-scan，P0 必须为 0
6. 回归自检（上面「硬约束」里那几条）
7. 汇报（≤25 行）：质询轮次与结论、借用的机制与落地方式、实际改了哪几处、未改条目与理由、自检结果
