# 方向 G · 数据密集型仪表板（印刷统计表 × 屏幕原生图表）

## 参考与借用（这一轮的重点）
- 借自 **Magic UI · Bento Grid**：非对称信息宫格 —— 落地为本页的「hairline 规则线切分网格」，不用圆角卡片，用 1px 线把屏幕切成不同权重的数据格（大 KPI / 区间条 / 宏量三联各占其位）。
- 借自 **Magic UI · Number Ticker**：数值变化滚动 —— 落地为大字号 KPI（870/509/421）切换份量、切屏时以 `tickflip` 位移动画重入，纯 transform/opacity。
- 借自 **Magic UI · Code Comparison 双栏拖动机制** → 位移对比 —— 落地为「今日区间迷你条」与「单菜热量区间条」：参考带(ochre 底) + 当前值(红 pin) 在同一条刻度上滑动，读「本处折算 vs 区间」。
- 借自 **Magic UI · Dotted Map 点语言** —— 落地为周视图「餐次完整度」7×3 点阵：实心=有记录、橙=含待估算、虚线空心=未记录。
- 借自 **Magic UI · Animated List**：追加/删除动画 —— 落地为新建一餐「添加菜品」列表的 `enter/leave` 位移动画。
- 借自 **Magic UI · Flickering Grid / Interactive Grid Pattern（克制版）** —— 落地为纸面 24px 横格 + feTurbulence 油墨颗粒，只作质地、不抢内容。
- 标杆参照：Linear Analytics（克制的信息密度）、Stripe Dashboard（图表可读性与数据可信感）、Vercel Analytics（每条线有意义）、Grafana/Datadog 的高级版（分析师天天盯的专业感）、Tremor / shadcn charts 的图表语言。

## 核心母题（一句话）
把「食堂热量记录」做成一张**印刷统计表**：细规则线切分、双线合计、点线引导、等宽/表格数字，屏幕原生图表（堆叠柱、区间条、点阵）长在表格骨架上，而不是套在圆角卡片里。

## 三个关键工艺细节
1. **图表全部可读**：周视图有 Y 轴刻度(0/600/1200/1800/2400)、单位(千卡)、`参考区间 1800–2200` 实测参考带、堆叠柱按早/午/晚分段并留 1px 纸色缝、缺记录日只留虚线基线（绝不画零高柱冒充 0）。柱体用印刷斜线 hatch 而非实色块。
2. **数字自洽**：所有数字运行时由菜品库 `DB` 计算，总数=明细之和（今日 360+509=870 与两张卡逐项吻合）；缺失一律 `null` 显示「未记录 / 待估算」，无 `0` 冒充。
3. **材质**：纸底=24px 横格 + 油墨颗粒(两层 SVG 噪声)，表头 1.5px 墨线、合计双细线、块间 1px hairline；主操作用表内「证件照位」（四角裁切标记 + 单线相机），非圆角药丸。

## 性能取舍
- 单文件 72 KB（预算 120 KB）；零外部依赖、零联网、系统字体栈 + 内联 SVG/CSS 纹理。
- 动画只动 `transform/opacity/width`，`prefers-reduced-motion` 全量降级。
- 图表用内联 SVG（无 Canvas/库）；点阵、条纹、颗粒全为 CSS/SVG，无位图。

## 质询迭代
- **第 1 轮（10 项，5 项必改）**：周图编码与图例不匹配、餐次明细缺合计双线与点线引导、新建页黑色满宽识别横幅像通用 SaaS 上传卡、今日两条区间条刻度不一致、餐次点阵列不对齐且只编码二值。
- **按单返工**：①周柱改「实墨/斜纹仅≈含待估算/浅灰未记全/红今日(叠加斜纹)/— 缺失占位」，图例一一对应；②明细加合计行 + 3px double rule + 标签→数值虚线引导；③黑色横幅换成表内「证件照位」（四角裁切标记 + 单线相机 + 无边框勾选框拍照）；④两条区间条统一 0–2400 标尺、补齐刻度、斜纹只覆盖实际区间、当前值端点标签；⑤点阵改 7×3 矩阵，列标题居中、列间竖线、每格带道数微数字、空餐「—」。
- **第 2 轮复核（要求质询代理先加载 skill）**：5 项必改**全部闭环**，档次 6.0→7.5/10，**可结案**；另附 3 条非阻断打磨项（今日柱红+斜纹叠加、拍照位四角框放大去外框、点阵按道数生成微点阵）已并入。
- **未改项**：点阵「每格一餐一点 + 道数数字」的语义冗余为兼顾可读性保留（按道数生成微点阵会牺牲 390 宽下的辨读）。
