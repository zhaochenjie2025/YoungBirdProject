# 卡路里拍立得 CalorieSnap

北邮食堂饮食记录的纯前端单页应用：拍下一道菜 → 确认菜品与份量 → 算出热量 → 存成一条饮食记录。

首版按 PRD v0.1 实现，免登录、记录只保存在当前浏览器，托管目标是 GitHub Pages。

## 快速开始

```bash
npm install
npm run dev          # 本地开发，http://127.0.0.1:5273
npm run verify       # 语义索引 + 菜品库 + 类型 + 单测 + 构建，全部通过才算合格
npm run smoke        # 浏览器端到端冒烟（需先 vite preview 起在 5274）
```

## 要配置什么

识别与膳食建议调用 DeepSeek，需要你自己的一把 API key：

1. 到 [platform.deepseek.com](https://platform.deepseek.com) 申请，建议单独建一把、额度设低。
2. 应用内「设置」页填入。默认只存在当前标签页，勾选「记住」才长期保存。
3. key 直接发往 `api.deepseek.com`，不经过任何中间服务器。

没有 key 时，搜索添加、手动补录、份量计算、保存历史全部照常可用。

## 已实现

- 新建/编辑一餐，拍照识别、搜索、手动补录混用，共用一份草稿
- 份量选择（半份/标准份/自定义克数），改份量后明细与汇总同步
- 待估算状态：菜品库外的食物可保存，标为「暂无数据」并计入待估算数量
- 今日页、单餐明细（含营养数据出处与份量来源）、历史页、周视图
- 记录存 localStorage，可导出/导入 JSON
- 膳食建议：单餐与单日两种范围，前端算数、模型只解释，建议里的异常数字会被标出

## 没做 / 待办

- **真实食堂数据**：菜品库 24 条为公开资料折算，份量为估重。PRD 要求的 20 类、称重样本、60 份实测餐食仍需团队采集。
- **识别准确率**：目前只在 13 张公开图片的干净子集上验证（13/13），样本量远不足 PRD 要求的 100 张独立测试图。
- **生产端点未联调**：本机没有 DeepSeek API key，识别与建议只在本地模型网关（Anthropic 格式）上验证过，OpenAI 格式的生产调用路径尚未用真实 key 跑通。
